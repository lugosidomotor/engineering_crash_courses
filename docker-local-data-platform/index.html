Section 01

Docker alapok: image, container, volume

Image = sablon. Container = futó példány. Volume = perzisztens adat.

ParancsLeírás
docker runContainer indítás
docker psFutó containerek
docker execParancs futtatás containerben

[1]
# Pull and run Python container
docker run -it python:3.11 python --version

# List running containers
docker ps

# Run with volume mount
docker run -v $(pwd)/data:/app/data python:3.11 ls /app/data
Output:

      POSTGRES_USER: admin

Section 06

Spark konténer Spark

Apache Spark standalone cluster Docker-ben.

[6]
# docker-compose.yml - Spark
  spark-master:
    image: bitnami/spark:3.5
    environment:
      - SPARK_MODE=master
    ports:
      - '8080:8080'
      - '7077:7077'

  spark-worker:
    image: bitnami/spark:3.5
    environment:
      - SPARK_MODE=worker
      - SPARK_MASTER_URL=spark://spark-master:7077
    depends_on:
      - spark-master
Output:
$ docker-compose up spark
Spark Master: running at spark://localhost:7077
Web UI: http://localhost:8080
Workers: 1 alive

Prometheus + Grafana Prometheus Grafana

Monitoring stack: metrics collection + dashboard.

[9]
# docker-compose.yml - Monitoring
  prometheus:
    image: prom/prometheus
    ports:
      - '9090:9090'

      - ./prometheus.yml:/etc/prometheus/prometheus.yml

      - prometheus

Section 10

Docker networking

Bridge, host, overlay. Service discovery, DNS.

HálózatLeírás
bridgeAlapértelmezett, izolált hálózat
hostHost hálózat, nincs izoláció
overlayMulti-host, Swarm/K8s
noneNincs hálózat
[10]
# Custom network for services
networks:
  data-platform:
    driver: bridge

services:
  postgres:
    networks:
      - data-platform
  spark:
    networks:
      - data-platform

# Services can reach each other by name:
# postgres:5432, minio:9000, spark-master:7077
Output:
$ docker network ls
NETWORK ID   NAME              DRIVER
abc123       data-platform     bridge
Section 11

Volumes és persistent data

Named volumes, bind mounts, backup/restore.

[11]
# Named volumes
volumes:
  pgdata:
  minio_data:
  spark_data:

# Backup strategy
# 1. pg_dump
docker exec postgres pg_dump -U admin webshop_pro > backup.sql

# 2. Volume backup
docker run --rm -v pgdata:/data -v $(pwd):/backup alpine tar czf /backup/pgdata.tar.gz /data
Output:
$ ls backup/
backup.sql  pgdata.tar.gz  minio_backup.tar.gz
Total size: 125MB

Section 14

Health checks, resource limits

Production-like best practices.

[14]
# Health check example
  postgres:
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready']
      interval: 10s
      timeout: 5s
      retries: 5

# Resource limits
  spark-worker:
    deploy:
      resources:
        limits:
          cpus: '2.0'
          memory: 4G
        reservations:
          memory: 2G

# Restart policy
    restart: unless-stopped
Output:
Health checks: All passing
Resource usage:
  postgres:     256MB / 1GB limit
  spark-worker: 1.8GB / 4GB limit
  grafana:      128MB / 512MB limit
